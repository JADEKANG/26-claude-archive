셜록작가/포셜록 발굴 결과를 guest-candidates.md에 바로 추가하지 말고, 먼저 유저에게 리포트 형식으로 보여주고 컨펌 받은 후 반영한다.

**Why:** 유저가 게스트 후보 품질을 직접 판단하고 싶어함. 자동 업데이트 시 낮은 품질 후보가 리스트에 섞일 수 있음.

**How to apply:** 발굴 완료 후 "이 사람을 추천하는 이유 + 최근 행보 + 채널에 미칠 영향" 형식으로 정리해서 보여주고, 유저 승인 후 파일 업데이트.

---

셜록작가는 반드시 스킬 Phase 0.5 워크플로우대로 실제 데이터 소스를 사용해야 한다. 일반 웹서치 프롬프트로 대체 불가.

**Why:** 셜록작가 페르소나의 핵심은 데이터 기반 판단. 임의 웹서치는 편향되거나 근거 없는 후보를 올릴 수 있음.

**How to apply:** 셜록작가 발굴 요청 시 반드시 Skill 도구로 sherlock-books 스킬을 실행하고, Phase 0.5의 4개 트랙(Amazon Bestsellers, NYT, Publishers Weekly, Goodreads + Hot New Releases + Movers & Shakers + 팟캐스트 서킷)을 실제로 fetch/검색해서 데이터를 수집한다. 추정은 반드시 [추정]으로 표시.

---

게스트 발굴 우선순위 기준: 버티컬 적합성보다 **시의성(최근 행보/화제성) + 스타성(인지도/캐릭터)** 가 더 중요. 버티컬은 후순위로 고려.

**Why:** 버티컬 맞춰도 화제성 없으면 조회수 안 나옴. 채널 성장이 우선.

**How to apply:** 발굴 시 "지금 이 사람이 왜 핫한가"를 먼저 설명하고, 버티컬 연결은 부가 정보로 제시.
